# 渠道错误、诊断日志与 UI 回归（2026-09-04）

> 展示方式已按用户后续确认调整：各渠道独立小图标，默认不显示错误文案或汇总卡，点开图标再查看详情。当前实施进度见 [渠道小状态组件](design/COMPACT-CHANNEL-STATES.md)。本文其余内容保留上一轮后端错误分类、日志与历史验证记录。

## 本次问题的原因

1. 截图中的 Google 返回 **HTTP 429**，属于渠道限流，不是截图权限错误，也不表示所有网络请求失败。旧版本把 ureq 错误直接转成字符串，导致包含查询文本的 URL 被显示在卡片里。由于当时没有持久化渠道诊断日志，无法追溯这一次请求的服务端 `Retry-After`，也不能断定限额按 IP、账户还是其他维度计算。[HTTP 429 规范](https://www.rfc-editor.org/rfc/rfc6585#section-4)
2. `.svc.failed .retry-svc` 仍沿用纯图标按钮的 **24×24 px** 固定尺寸；添加“重试此渠道”后，文字溢出并挤成竖排。
3. 本地图标字体是子集，未收录的图标名称会显示成英文字符。现在公共图标入口使用已收录字形的码点；未知名称回退到信息图标，不再把英文名称塞进布局。

## 错误与交互

- 错误通过结构化类别、HTTP 状态和冷却时间传递，默认卡片只显示图标、简短标题、解释与恢复操作。区分限流、超时、连接失败、服务不可用、凭据/配置错误、语向不支持、空响应等。
- 原文、其他渠道的成功译文保留。全部失败时给出轻量空态；配置错误引导到设置，不盲目提示重试。
- “诊断信息”默认折叠，可复制安全诊断摘要或查看本机日志。原始响应正文、完整 URL、原文和密钥不进入这些错误 UI/诊断数据。
- 文字按钮按内容撑开，图标不挤占文字空间；按钮组空间不足时整颗按钮换行。历史操作、权限页、设置行与确认对话框共用这些约束。
- 保留原有琥珀色/中性灰视觉语言，使用轻量图标和文字，不增加图片请求或 UI 框架。尊重减少动态效果设置。

## 稳定性与性能边界

| 情形 | 行为 |
| --- | --- |
| 渠道限流 | 优先尊重有效 `Retry-After`（整数秒或 HTTP 日期）；同时采用从 60 秒开始的本地指数退避，本地部分最多 900 秒，再加 0–5 秒抖动 |
| 临时连接/超时/5xx 错误 | 5 秒起的短退避，本地部分最多 60 秒；服务端更长的等待时间仍生效 |
| 冷却期间再次翻译 | 后端跳过受限渠道，返回剩余等待时间；其他渠道正常运行。重启会清除进程内冷却，不建议用重启绕过限流 |
| 冷却结束 | 只恢复手动重试按钮，不自动发送原文，不产生重试循环 |
| 并发与取消 | 同一渠道最多 1 个实际工作者，全局最多 8 个。取消后同步 HTTP 可能仍在运行，继续占槽直到真正结束；其限流结果仍能建立冷却 |
| 旧重试路径 | 移除 Bing 对任意失败的立即重试、以及有道缺少结果时的延时重复请求 |
| 日志 | 单后台写线程、256 条有界队列，生产者非阻塞；每文件 1 MiB，最多 4 个文件。失败或队列满不阻塞翻译，设置中提示写入异常/跳过记录 |
| 倒计时 | 只在存在冷却且页面可见时运行一个秒级定时器；页面隐藏或冷却结束停止 |

极端到超出平台时间表示范围的 `Retry-After` 使用一致的 24 小时兜底，避免溢出或 UI 与后端等待时间不一致。日志是尽力记录，不保证强制退出/崩溃时最后几条队列记录落盘。

以上措施控制资源、等待和恢复方式，**不等于承诺免费上游接口永不失败**；不会偷偷启用新渠道、自动修改服务开关或绕过上游限流。

## 如何查看日志

新版运行后：设置 → 关于 → 诊断与反馈 → **查看日志**；错误卡片展开诊断信息也可进入。

macOS 路径由 Tauri `app_log_dir` 解析，当前 Bundle ID 对应：

```text
/Users/lucas/Library/Logs/com.lucas.translate/diagnostics.jsonl
```

保留渠道、错误类别、HTTP 状态、耗时、应用版本、时间、冷却秒数与随机请求/诊断 ID。截图/识别仅记录阶段是否成功和耗时，不记录图片或识别正文。历史/收藏数据库不属于诊断日志；其原有存储行为未改变。

排查同一问题时，用错误卡片复制的 **诊断 ID** 找到最初失败记录；后续冷却跳过记录沿用这个 ID。新日志无法还原旧版本没有记录的失败。
