# Lucas 统一状态系统 · 设计提案

状态：**历史草案，已被用户后续意见替代，不作为实施依据**。用户确认了角色形象，但明确要求小尺寸、各渠道独立 loading、失败默认只有图标，不接受全局汇总大空态。当前规范见 [渠道小状态组件](COMPACT-CHANNEL-STATES.md)。以下保留原提案供追溯。

## 1. 要解决的问题

当前 `card(r)` 对每个失败渠道调用同一个错误渲染函数。这统一了部分代码，却没有统一页面反馈：用户仍会看到重复错误卡片、重复操作和多个等待指示。

目标：**渠道提供数据，任务统一汇总，基础组件负责展示。** 同一原因在任何渠道上均使用相同的视觉和恢复语义；同一任务只出现一个反馈入口。

非目标：不重做翻译结果内容卡、不改变服务开关、不自动增加付费渠道、不假设 UI 能消除上游错误。

## 2. 视觉方向：小译团

暂定一个奶油色对话气泡角色，使用折角、点状眼睛、小手和少量琥珀色点缀。可爱来自一致的轮廓和动作，不依赖 emoji、不同风格的素材或大量感叹号。

六个姿态：

| 状态 | 角色表现 | 适用场景 |
| --- | --- | --- |
| 待开始 | 轻轻招手 | 初次打开、无输入 |
| 进行中 | 思考，三个小点 | 翻译、截图识别、读取记录 |
| 暂无内容 | 看向空白气泡 | 无历史、无收藏、没有识别到文字 |
| 暂未完成 | 微微歪头，轻困惑 | 各渠道/网络/超时失败统一使用 |
| 需操作 | 指向提示 | 未配置、需要系统权限 |
| 已完成 | 小幅确认手势 | 必要的短反馈，不占据译文区域 |

设计约束：

- 暖色强调 + 中性背景；提供明暗主题，不按渠道品牌颜色改状态插画。
- 插画支持 80 / 32 px 两种尺寸；16 px 按钮内只保留清晰的动作符号，不缩成难认的小脸。
- 概念板的柔和质感在落地时简化为轻量本地 SVG；它是方向参考，不直接把整张大图塞入应用。图标不依赖字体 ligature。
- 失败表情中性友善，不用庆祝/撒娇/流泪表达出错。系统权限提示不卖萌到模糊风险。
- 状态标题建议 15 px / 600，正文 12–13 px；辅助文字保持可读对比度。可爱插画不替代原因与操作说明。

## 3. 基础组件：同一结构，三个规格

统一内容顺序：**状态图形 → 标题 → 一句说明 → 恢复操作 → 可选详情**。

### StateView

`state`: idle / loading / empty / error / action-required / success。

`variant`：

- **full**：用于当前内容区没有可用内容，80 px 插画居中。影响仅限本次任务的结果区域，不覆盖输入区或整台应用。
- **compact**：用于已有可用内容，32 px 插画横排。出现在结果列表下方一个稳定的状态区域，无渠道级重复状态卡。
- **inline**：用于按钮、设置字段及短反馈。沿用相同文案规则、颜色和动作符号，保持轻量。

数据只允许传入语义状态、任务类型、简短文案、计数、恢复动作、详情数据。**不接收 provider-specific class、颜色、插画或任意 HTML。** 渠道名称只出现在结果标题和详情中。

### StateActions

- 一组共享操作，最多一个主要动作 + 一个次要入口；固定最小高度 32 px，宽度由文字决定，圆角 9 px，间距 8 px。
- 可执行的短按钮文案：重新翻译、重试未完成、打开设置、取消。
- 空间不足时整颗按钮换行，禁止在固定图标框中放文字。禁用和处理中都不改变按钮宽度。
- 技术原因与日志入口不争夺主要按钮位置，统一置于「详情」展开区域。

### StateDetails

在同一位置按需展开为简洁列表：渠道名、原因、是否可恢复/冷却时间。无插画、无独立错误卡、无多组主按钮。列表中可提供必要的设置定位链接，但不重复全套动作。

诊断 ID、复制诊断、查看日志归入详情的诊断子区；默认不展示 HTTP/URL/堆栈/输入正文。渠道详情保留事实可追溯性，不因聚合而丢失差异。

## 4. 页面汇总规则

| 当前结果 | 唯一主要反馈 | 内容保留 |
| --- | --- | --- |
| 无结果，仍有渠道等待 | full loading「正在翻译…」 | 原文保留；已失败渠道暂记在详情，不提前判为整体失败 |
| 已有结果，仍有渠道等待 | compact loading「已有 2 个结果，正在等待其余回复」 | 结果到达即可使用，不等待最慢渠道 |
| 部分成功，其余终止失败 | compact error「2 个渠道暂未完成」 | 只展示成功结果卡；失败汇总一次 |
| 全部终止失败，无可用结果 | full error「这次没能完成翻译」 | 原文保留，没有三张渠道错误卡 |
| 全部成功 | 不显示多余的状态插画 | 正常结果；底栏简短计数 |
| 用户取消 | compact 或 full 中性反馈，取决于是否已有内容 | 保留已完成结果，不标成网络错误 |
| 未配置渠道 / 需要权限 | action-required | 不伪装成网络错误；在受影响内容区提供操作 |

只有任务对应的可用结果才能决定 full/compact；不把上一次输入的译文当作本次成功。恢复单个/多个失败渠道时保留同任务已有结果。新的用户输入属于新任务；旧请求的迟到消息不能改变新状态。

聚合范围是“当前任务/内容区域”，不是把全应用所有错误混成一条：例如翻译仍在进行时，设置保存失败必须在设置中提示，不能把翻译页面替换成错误空态。

## 5. 恢复动作与混合失败

- **部分成功**：主要动作「重试未完成」，只重试失败且当前允许重试的渠道，不重跑成功渠道。
- **全部失败且可重试**：「重新翻译」；不启用原本关闭的渠道。
- **所有待恢复渠道都在冷却**：同一错误组件，显示明确等待时间；重试按钮禁用。到期只恢复可点击，不自动请求。
- **凭据/配置问题**：主要动作「打开设置」，不提供无效的盲目重试。
- **混合错误**：若有可重试项，优先重试这些项，在说明中标明「可重试 1 个，其余需等待或配置」；其余原因在详情中保留。若没有可重试项但需要配置，主要动作改为设置。
- **系统权限**：展示真实操作指引；只有系统确实要求重新启动时提供重启动作，不将所有失败都归因于权限。
- 不能凭一个渠道连接失败就宣布「你已离线」；未确认的网络故障用「暂时连接不上服务」。

这使展示统一，但仍保持恢复操作正确，不把 429、凭据无效和断网混为一谈。

## 6. 文案基线

| 场景 | 标题 | 说明 / 主要操作 |
| --- | --- | --- |
| 初次打开 | 想读懂什么？ | 输入文字，或按 ⌥S 截图翻译；不额外堆按钮 |
| 翻译等待 | 正在翻译… | 正在等待 3 个渠道的回复 / 取消 |
| OCR 等待 | 正在读图中的文字… | 完成后会继续翻译 / 取消；静默 OCR 使用符合其流程的说明 |
| 全部失败 | 这次没能完成翻译 | 原文已保留，可以稍后再试 / 重新翻译 |
| 部分失败 | 2 个渠道暂未完成 | 已有译文可以继续使用 / 重试未完成 |
| 限流等待 | 这次没能完成翻译 | 服务暂时受限，约 1 分钟后可重试；到期恢复按钮 |
| 无历史 | 这里还没有翻译足迹 | 完成一次翻译后，记录会出现在这里 |
| 无收藏 | 把好用的译文留在这里 | 在历史记录中收藏后，就能方便地找回来 |
| OCR 无文字 | 这张图里还没找到文字 | 试着框选文字更清晰的区域 / 重新截图 |
| 用户取消 | 已停止等待 | 原文与已完成的译文都还在 |

原则：标题讲发生了什么，说明讲内容是否保留，操作讲下一步。语气温暖简洁，不责怪用户，不重复「网络错误」，不为了活泼而使用「罢工」「偷懒」等掩盖原因的表达。

## 7. Loading 与微动效

- 操作后立即给出状态反馈；复杂等待插画可延后约 150 ms 出现，避免瞬时任务闪屏。这个阈值是待验证的设计初值，不额外延迟真实结果。
- 无真实进度时只显示等待状态，不编造百分比；首个成功结果到达即展示，汇总组件切为 compact。
- 约 8 秒后可补充「这次稍慢，可以继续等待或取消」，沿用现有请求超时边界；不无限转圈。
- 普通状态切换 160–200 ms，优先透明度；插画位置和按钮尺寸稳定。loading 仅一处点状轻动效，错误/空态默认静止。
- 页面隐藏时暂停动画；`prefers-reduced-motion` 使用静态状态；屏幕阅读器只播报有意义的阶段变化，不逐秒播冷却时间。
- 重试按钮内反馈用于立即防重入，不额外再叠一套全页 loading；原有结果不闪退、不被遮住。

进度展示的位置一致、说明准确、允许取消等原则参考 [Apple Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)。

## 8. 全局覆盖与验收

覆盖：主翻译页面、OCR、历史/收藏、设置加载/保存、复制操作、权限指引。局部字段校验仍贴近字段，删除确认仍使用确认对话框，不将它们强行替换成大插画。

设计验收用同一套样例：

1. 三个渠道同因失败：只有一个状态组件、一组恢复操作。
2. 渠道失败顺序互换：插画、布局和文案规则不改变。
3. 两成功、一失败、一个等待：译文可用，只有一个 compact 汇总，不能误显示全部失败。
4. 混合 429、凭据错误与连接失败：详情准确，主要动作只作用于可恢复项。
5. 冷却、取消、超时、新输入、迟到结果：没有旧状态回写、假进度或 loading 永不结束。
6. 明暗主题、380 px 主窗口、320 px 压力宽度、580 px 设置最小宽度和文本放大：无竖排按钮、无溢出；短文案保持完整。
7. 空历史、空收藏、无文字 OCR：同一角色和布局规范，文案与操作适配各自场景。
8. 键盘焦点、减少动态效果、屏幕阅读器、离线素材：状态均可理解和操作。

简短、友善、可恢复、避免多重重复提醒的原则参考 [USWDS Alert](https://designsystem.digital.gov/components/alert/)；无内容时按上下文给出指引参考 [Carbon Empty states](https://carbondesignsystem.com/patterns/empty-states-pattern/)。

## 9. 确认后的实施顺序

1. 确认角色方向与三种组件规格；完成 full/compact 的明暗主题定稿。
2. 制作本地轻量插画与共享状态组件，不由渠道控制样式。
3. 接入任务汇总层，移除重复的渠道错误/等待卡。
4. 迁移 OCR、历史、收藏、设置等状态并补齐边界样例。
5. 完成组件视觉回归与原生 WKWebView 验收后，再重新打包安装。

当前需要确认的核心是「小译团的视觉方向」与「一个任务只出现一个汇总反馈」，而不是先继续修补现有失败卡片。
